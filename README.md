# risingosr_patches_zephyr

RisingOS Revived 9 (Android 17 / `CP2A`) for the **Redmi Note 17 4G**
(codename `zephyr`, SM6225-AF / `bengal`), built from the working LineageOS
24.0 device port plus only the patches RisingOS actually needs.

This repository is the third leg of the port:

| Repository | Holds |
|---|---|
| `uzbforce/android_device_xiaomi_zephyr` (`lineage-24.0`) | device tree: `BoardConfig.mk`, product makefiles, `rootdir/`, `configs/`, `sepolicy/`, overlays, recovery files, local manifest |
| `uzbforce/android_vendor_xiaomi_zephyr` (`lineage-24.0`) | blobs extracted from the stock firmware |
| **this repository** | patches against RisingOS Revived source projects, plus the local manifest and the Rising product configuration |

The SM6225 platform repos (`hardware/qcom-caf/common`,
`hardware/qcom-caf/sm6225/*`, `device/qcom/sepolicy_vndr/sm6225`) are pinned by
`local_manifests/zephyr.xml` and mirrored under the same `uzbforce` org.

## Resulting build

```text
Lunch target : lineage_zephyr-cp2a-userdebug
Build ID     : CP2A.260605.016
Package type : VANILLA (WITH_GMS := false, no vendor/gapps)
Maintainer   : uzbforce
Chipset      : Snapdragon 6s Gen2
Blur         : enabled (TARGET_ENABLE_BLUR := true)
Signing      : vendor/lineage-priv/keys; mka bacon produces a release-key-signed OTA
Kernel       : prebuilt 5.15.194-android13-8 from the stock firmware
```

`RISING_BUILDTYPE` is `COMMUNITY` because zephyr is not in
`vendor/official_devices`. To make it `OFFICIAL`, add `zephyr` to
`vendor/official_devices/OTA/risingOS.devices` and `uzbforce` to
`risingOS.maintainers`; nothing else in this port changes.

`mka bacon` writes these artifacts under `out/target/product/zephyr/`:

```text
RisingOS-9-<date>-VANILLA-COMMUNITY-zephyr-ota.zip        # signed OTA
RisingOS-9-<date>-VANILLA-COMMUNITY-zephyr.zip            # target-files package
RisingOS-9-<date>-VANILLA-COMMUNITY-zephyr-ota.zip.sha256sum
```

`lineage_zephyr-ota.zip` is hard-linked to the RisingOS OTA, so both names are
the same file. The built `system/build.prop` carries `ro.build.type=userdebug`,
`ro.build.id=CP2A.260605.016`, `ro.build.version.release=17`,
`ro.build.version.sdk=37`, `ro.custom.blur.enable=true`,
`ro.rising.maintainer=uzbforce`, `ro.rising.chipset=Snapdragon 6s Gen2` and
`ro.rising.packagetype=VANILLA`; no GMS/Play Store packages are installed.

The OTA is signed with `vendor/lineage-priv/keys/testkey`, whose `.pk8` and
`.x509.pem` are byte-identical to `releasekey` in this checkout. The
`META-INF/com/android/otacert` fingerprint therefore matches
`releasekey.x509.pem`:

```text
9E:6F:94:77:65:30:31:BE:41:30:6D:33:DF:7E:EC:63:CF:FB:16:98:83:DB:5A:77:15:7A:A3:DB:7C:97:EE:AC
```

If you rotate the release key, replace both files (or point
`PRODUCT_DEFAULT_DEV_CERTIFICATE` at `releasekey`) so the OTA follows it.

`zephyr.json` is generated by `vendor/rising/build/tools/createjson.sh`. With no
`vendor/official_devices/OTA/device/VANILLA/zephyr.json`, its `maintainer`,
`oem`, `device`, `download` and `buildtype` fields are empty and the script
prints "There is no official support for this device yet". This is upstream
behavior for an unofficial device; the maintainer is still in
`system/build.prop`. Adding zephyr to `vendor/official_devices` (above) supplies
those fields.

## Fresh checkout

```bash
repo init -u https://github.com/RisingOS-Revived/android -b seventeen --git-lfs
git clone https://github.com/uzbforce/risingosr_patches_zephyr \
    risingosr_patches_zephyr
cp risingosr_patches_zephyr/local_manifests/zephyr.xml .repo/local_manifests/
repo sync -c --no-clone-bundle --optimized-fetch --prune --force-sync -j"$(nproc --all)"
```

The local manifest fetches the device tree, vendor blobs and SM6225 platform
repos, replaces
RisingOS' `hardware/qcom-caf/common` with the SM6225-aware fork, and repeats the
`soong_namespace` linkfiles for every other `hardware/qcom-caf/*` platform dir
(the fork replaces Lineage's common project, so those links would otherwise be
lost and every platform tree would be parsed in the default namespace).

Two inputs are intentionally **not** in `repo`:

1. **Prebuilt kernel tree** — `device/xiaomi/zephyr-kernel` (kernel image, DTBs,
   `vendor_dlkm`/`system_dlkm`/`vendor_ramdisk` module sets and the uapi
   `kernel-headers`). It is not a repo project. For the exact build, copy the
   tree from the working checkout:
   `rsync -a /path/to/working-checkout/device/xiaomi/zephyr-kernel device/xiaomi/`.
   The working tree carries the ramoops DT patch and the pre-generated headers.
   To rebuild it from the stock package instead, run
   `device/xiaomi/zephyr/tools/gen-prebuilt-kernel.py` and
   `device/xiaomi/zephyr/tools/gen-kernel-headers.sh` as described in the device
   tree README (the header step needs the `sched_param` guard in
   `kernel/xiaomi/zephyr`).
2. **Kernel source clone** — `kernel/xiaomi/zephyr` from
   `MiCode/Xiaomi_Kernel_OpenSource`, branch `zephyr-w-oss`, with the techpack
   and vendor DTS changes. On the prebuilt-kernel route it is only needed for
   the kernel headers the vendor HALs compile against; `BoardConfig.mk` exports
   the prebuilt `kernel-headers` through the `lineageVarsPlugin` namespace, so
   the build does not run `headers_install`. A source rebuild needs the kernel
   patches from the Lineage patch repository.

Release keys go to `vendor/lineage-priv/keys` (the `keys.mk` from
`lineage/scripts/lineage-priv-template` plus the zephyr `releasekey`, `avb` and
per-APEX overrides). `lineage_zephyr.mk` includes
`vendor/lineage-priv/keys/keys.mk`, so `mka bacon` signs the target files, APKs
and OTA with those keys; no separate `rise sb` step is required. The private keys
are deliberately not in this repository. For a byte-identical OTA, copy
`vendor/lineage-priv/keys` from the working checkout; with new keys the build is
functionally the same but the OTA certificate (and the fingerprint above)
changes.

## Applying

```bash
./risingosr_patches_zephyr/apply.sh                 # uses $ANDROID_BUILD_TOP, else $PWD
./risingosr_patches_zephyr/apply.sh /path/to/risingos
```

Patches are applied in filename order. Each is validated with
`git apply --check` first; already-applied patches are skipped, and a one-line
context reduction (`-C1`) is used for RisingOS copies of AOSP projects that
differ by a nearby line. The script exits non-zero if any patch failed.
Nothing is committed; `git -C <project> diff` still works. The checked-in set
was verified with `git apply --check` against the pristine `HEAD` of each
project in the RisingOS `seventeen` checkout.

## Capturing a new change

```bash
./risingosr_patches_zephyr/capture.sh frameworks/base "fix the next thing"
```

It writes `patches/frameworks/base/0001-fix-the-next-thing.patch`, includes
untracked files as `new file mode` entries, and leaves the working tree alone.
Delete the previous patch for that project when re-capturing a series.

## What is in here

### Used from `lineage_patches_zephyr`

| Patch | Fixes |
|---|---|
| `bootable/recovery` | Android 17 libc++ no longer transitively includes `<memory>`, `<string>` etc.; add direct includes to recovery UI/sideload/volume-manager sources |
| `external/tinyalsa` | vendor mixer can expose an enum entry with no text; don't pass NULL to `strncpy()`, make the index bound inclusive-safe |
| `frameworks/av` | codec2/OMX fixes: export `GraphicBufferSource::getHGraphicBufferProducer()` in both flag variants, make `OmxInfoBuilder` use `tryGetService()` (the stock OMX HAL is 32-bit, this product is 64-bit only), and test the local `AidlGraphicBufferSource` path before asking the HIDL store for an input surface |
| `frameworks/base` (adapted) | `StorageManagerService` runs codec enumeration off its handler thread and retries an unmounted emulated volume 15 s after boot; `HardeningEnforcer` keeps background media focus when only the while-in-use capability is missing; new `TelephonyBaseUtilsStub.isMiuiRom()` stub for the stock `QtiTelephony`/`org.codeaurora.ims` blobs; `DozeSensors` picks the wakeup UDFPS sensor and fills its coordinates from `config_udfps_sensor_props`; `UdfpsController` ignores the Goodix vendor acquired events, extends the AOD finger-up timeout to 2.5 s, ignores touch-up during AOD and honors `config_screen_off_udfps_default_on`; the legacy keyguard occlusion is mirrored into the notification-shade window |
| `hardware/interfaces` | skip the multi-STA "primary connection" hint when only one STA iface exists; the QCA6 driver answers `-ENODEV` and the AIDL HAL otherwise tears down `createStaIface` |
| `hardware/lineage/compat` | export the protobuf 3.9 symbols (`CopyWithSourceCheck`, `ParseFromString(const std::string&)`, legacy `AssignDescriptors`) and out-of-line `DynamicDisplayInfo`/`StaticDisplayInfo` the stock `qccsyshal@1.2` / `libgui_vendor` import |
| `hardware/lineage/interfaces` | drive the vendor FOD `extCmd` from `onPointerDown`/`onPointerUp` so the stock Goodix `fingerprint.goodix_fod.so` capture window arms, set/release local 1000-nit HBM on press with a 5 s watchdog |
| `hardware/qcom-caf/thermal` | the SKIN ramp reads `xo-therm` (idle ~39.5 C), so thermalservice starts at `MODERATE` and camera video is refused; shift the ramp up ~5 C |
| `hardware/qcom-caf/wlan` | same unsupported `CONCURRENT_STA_PRIMARY` command through the legacy HAL; report success without sending it |
| `lineage-sdk` | don't throw from `LineageGlobalActions` when the `lineageglobalactions` service is absent; return an empty/local list |
| `packages/apps/Dialer` | follow `AudioManager.getCommunicationDevice()` for proximity blanking instead of a stale Bluetooth route |
| `system/libbase` | keep the pre-`string_view` `WriteStringToFd(const std::string&, borrowed_fd)` and `Trim(const std::string&)` symbols the prebuilt health/sensors HALs import |
| `system/sepolicy` | treat an absent `treble_labeling_violators` attribute as an empty set instead of aborting `treble_labeling_tests` |
| `system/vold` (adapted) | add the standard library includes Android 17's libc++ no longer pulls in |
| `tools/extract-utils` | symlink modules take their soong name from the path; `vendor/bin/[` is not a valid identifier |
| `vendor/lineage` | `lineage_generator` hands an unknown `$(VAR)` back for a later expansion, breaking a prebuilt-kernel tree during analysis; expand undefined variables to nothing. Also fall back to the unpinned build manifest when some projects are intentionally absent |
| `vendor/qcom/opensource/power` | declare `interface aidl` in the QTI power rc and join the input group so the FTS double-tap gesture can be armed |
| `vendor/qcom/opensource/vibrator` | select the LED trigger only when its attributes are missing, chown the attributes and restart once boot completes; the `system`-uid HAL otherwise cannot open them |
| `device/xiaomi/zephyr` (Rising-specific) | set `RISING_MAINTAINER`, `RisingChipset`, `RisingMaintainer`, `TARGET_ENABLE_BLUR := true`, `WITH_GMS := false`, drop the GApps inherit, and list the `cp2a` lunch choices |

### Deliberately excluded as Lineage-specific

| Patch | Why RisingOS does not need it |
|---|---|
| `packages/apps/Launcher3/0001-respect-the-live-window-blur-state.patch` | RisingOS' Launcher3 already has the live `WindowBlurState` plumbing and its own blur toggles; the Lineage patch would duplicate Lineage-only blur logic |
| `packages/apps/Settings` blur hunks (`display_settings.xml`, `WindowBlurPreferenceController`, `BlurSwitchPreference` default) | RisingOS already ships `BlurSettings` / `BlurSettingsPreferenceController` and its own accessibility blur switch; the Lineage preference is not used. Only the non-blur dumpstate ANR fix is kept |
| `frameworks/base` `BlurController` hunk (blurless default) | Lineage-specific: Lineage opts into blur; this build sets `ro.custom.blur.enable=true` through `TARGET_ENABLE_BLUR := true`. Keeping the hunk would also fight RisingOS' display blur setting |
| `frameworks/base` face-indicator / keyguard UI hunks (`FaceUnlockImageView`, `FaceScanningProviderFactory`, `KeyguardIndicationAreaTop`, keyguard blueprints, `StatusBarKeyguardViewManager` face callbacks, `BiometricPromptLayoutState`, `BiometricViewSizeBinder`, `PromptViewModel`, face drawables/dimens, `KeyguardIndicationController`) | these are Lineage's Paranoid Sense status-bar/keyguard presentation. RisingOS already ships its own `FaceUnlockController` / `FaceUnlockImageView` / Sense provider and its own keyguard blueprint; porting Lineage's would conflict |
| `frameworks/base` IMS/VoLTE status-bar-icon config hunks | RisingOS has its own status-bar icon set; the Lineage `config_statusBarIcons`/drawable additions are Lineage SystemUI-specific |
| `frameworks/base` `services/core/Android.bp` Sense dependency | already present in the RisingOS tree |
| `build/soong/0002-sync-the-current-build-ui-changes.patch` | already present in RisingOS `ui/build/rbe.go` |
| `device/qcom/sepolicy_vndr/sm6225/0001-0003` | already committed in the pinned `uzbforce/android_device_qcom_sepolicy_vndr_sm6225` repo |
| `hardware/qcom-caf/sm6225/audio/primary-hal/0001-do-not-build-libqcompostprocbundle` | already committed in the pinned `uzbforce/android_hardware_qcom-caf_sm6225_audio_primary-hal` repo |
| `kernel/xiaomi/zephyr/0003`, `0004` | the build uses the prebuilt kernel tree; the kernel source clone already carries these changes. Re-apply them only if rebuilding the kernel from `MiCode/Xiaomi_Kernel_OpenSource` |

The full original set is still in
`uzbforce/lineage_patches_zephyr` for the LineageOS 24.0 tree; this repository
is the filtered, RisingOS-adapted subset.

## Verifying the OTA signature

```bash
ls out/target/product/zephyr/RisingOS-*ota.zip
unzip -p out/target/product/zephyr/RisingOS-*ota.zip META-INF/com/android/otacert \
    | openssl x509 -noout -fingerprint -sha256
openssl x509 -in vendor/lineage-priv/keys/releasekey.x509.pem \
    -noout -fingerprint -sha256
```

The two fingerprints must match.
